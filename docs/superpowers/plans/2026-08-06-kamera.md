# Kamera obok udostępniania ekranu — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Uczestnik lobby może włączyć kamerę niezależnie od udostępniania ekranu; każdy strumień jest osobnym kafelkiem.

**Architecture:** Ekran i kamera to dwa niezależne strumienie. Połączenia WebRTC są kluczowane przez `${peerId}:${kind}`, więc włączenie kamery zestawia nowe połączenie zamiast renegocjować działające. Serwer sygnalizacyjny trzyma nadających jako zbiór par `peerId:kind`.

**Tech Stack:** TypeScript, Electron 33 + React 18 (companion-app), Node + `ws` (signaling-server), vitest, e2e przez CDP.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-06-kamera-design.md`.
- **TDD obowiązuje.** Test przed implementacją, obejrzany na czerwono. Nie wolno pisać kodu produkcyjnego bez wcześniej oglądanego czerwonego testu.
- Komentarze i komunikaty dla użytkownika po polsku; identyfikatory w companion-app po angielsku, w signaling-server po polsku — tak jak w istniejącym kodzie.
- **Brak zgodności wstecz w protokole** (decyzja właściciela projektu): `kind` jest wymagane.
- Kamera nigdy nie ma ścieżki audio — `audio: false`.
- `contentHint`: `'detail'` dla ekranu, `'motion'` dla kamery.
- Po każdym zadaniu: `npm run typecheck` w dotkniętym pakiecie musi przechodzić czysto.
- Nazwa `kind` w `SignalPayload` jest już zajęta przez rodzaj sygnału (`offer`/`answer`/`ice`). Rodzaj strumienia nazywa się tam `stream`.

export type StreamKind = 'screen' | 'camera'

export interface StreamRef {
  peerId: string
  kind: StreamKind
}

const STREAM_KINDS: readonly string[] = ['screen', 'camera']

function isStreamKind(value: unknown): value is StreamKind {
  return typeof value === 'string' && STREAM_KINDS.includes(value)
}

/**
 * Stara wersja aplikacji wysyla start-stream bez pola kind. Rozpoznajemy to
 * osobno, zeby dac uzytkownikowi instrukcje zamiast zagadki.
 */
export function isLegacyStreamMessage(raw: unknown): boolean {
  if (typeof raw !== 'object' || raw === null) return false
  const obiekt = raw as Record<string, unknown>
  if (obiekt.type !== 'start-stream' && obiekt.type !== 'stop-stream') return false
  return !isStreamKind(obiekt.kind)
}
```

W typie `ClientMessage` zmień oba warianty na `{ type: 'start-stream'; kind: StreamKind }`
i `{ type: 'stop-stream'; kind: StreamKind }`. W `parseClientMessage`, w gałęziach
obsługujących te dwa typy, zwróć `null`, gdy `isStreamKind(obiekt.kind)` jest fałszem;
w przeciwnym razie zwróć `{ type, kind: obiekt.kind }`.

W `ServerMessage` zamień `streamers: string[]` na `streams: StreamRef[]` w wariancie
`joined` oraz dodaj `kind: StreamKind` do `stream-started` i `stream-stopped`.

/** Klucz strumienia w pokoju. Jedna osoba moze nadawac ekran i kamere naraz. */
function kluczStrumienia(peerId: string, kind: StreamKind): string {

  const [peerId, kind] = klucz.split(':')

}

export type CameraResolution = '480p' | '720p' | '1080p'

export const CAMERA_DIMENSIONS: Record<CameraResolution, { width: number; height: number }> = {
  '480p': { width: 854, height: 480 },
  '720p': { width: 1280, height: 720 },
  '1080p': { width: 1920, height: 1080 }
}

export interface CameraSettings {
  /** null = urządzenie domyślne systemu. */
  deviceId: string | null
  resolution: CameraResolution
  fps: number
}

export const DEFAULT_CAMERA_SETTINGS: CameraSettings = {
  deviceId: null,
  resolution: '720p',
  fps: 30
}

export function cameraConstraints(settings: CameraSettings): MediaStreamConstraints {
  const rozmiar = CAMERA_DIMENSIONS[settings.resolution]
  const video: MediaTrackConstraints = {
    width: { ideal: rozmiar.width },
    height: { ideal: rozmiar.height },
    frameRate: { ideal: settings.fps, max: settings.fps }
  }
  // deviceId: null wywala getUserMedia — brak wyboru to brak pola.
  if (settings.deviceId) video.deviceId = { exact: settings.deviceId }
  return { video, audio: false }
}
```

- [ ] **Step 1: Przebuduj stan strumieni**

W `useLobby.ts` zamień mapę `peerId → MediaStream` na klucz złożony:

```ts
export interface RemoteStream {
  peerId: string
  kind: StreamKind
  stream: MediaStream
}

// Klucz zlozony, bo jedna osoba moze nadawac ekran i kamere naraz.
const [remote, setRemote] = useState<Map<string, RemoteStream>>(new Map())

const onRemoteStream = (peerId: string, kind: StreamKind, stream: MediaStream | null): void => {
  setRemote((poprzednie) => {
    const kolejne = new Map(poprzednie)
    const klucz = connectionKey(peerId, kind)
    // null = koniec TEGO strumienia. Drugi strumien tej samej osoby zostaje.
    if (stream) kolejne.set(klucz, { peerId, kind, stream })
    else kolejne.delete(klucz)
    return kolejne
  })
}
```

Sprzątanie po `peer-left` musi usunąć **wszystkie** wpisy o danym `peerId`, a nie
jeden — inaczej po wyjściu osoby z kamerą zostałby osierocony kafelek.
